Why must the "snake charmer" always be depicted as a human playing music to a snake? Snakes can be charming too! Why, I'll prove it. Behold, my tunes!

In this project, we took a song and played it through the Lilypad buzzer. When a button (A9 pin) is pressed, the song plays and stops after the button is released. To code the notes, I assigned each note the right frequency (which I found [here](https://electricalelibrary.com/en/2018/08/26/arduino-tutorial-part-9-music-and-keypad/) on the Electricale Library). The song I chose was "Creator" by Lena Raine, one of my favorite Minecraft OSTs (original soundtracks). The song is long and complicated so I only managed to code the first minute of it. I worked through this assignment by listening to "Creator" on Spotify while using a virtual piano in another tab to help me isolate the notes. 

One of the first things I tried to do was play multiple notes by switching between them quickly (like how we turned the LEDs to lower brightnesses) but the buzzer couldn't keep up with that. So instead I played around with the tempo to give the illusion that multiple instruments were playing at the same time. I split the song into ten chunks, each with an if statement checking to see if the button was pressed before continuing the song.
### Variables
- My code uses 26 different notes across three octaves. Each note is represented by their key and octave, for example "E6". While I was assigning variable names, I learned that Arduino doesn't like non-alphanumeric characters, so I represented my sharps like "Fh6". I also realized that I can't call a value "A6" or Arduino would think I'm talking about the pin A6. So every *A* note is labeled with an underscore, like "A_6".
- I made the variable "TEMPO" to serve as my delay between the notes, and the speed of the song depends on what value the tempo is set to. Musically, I imagine TEMPO as representing the quarter-notes. If I need a longer or shorter note, I multiply TEMPO by my desired length.
- I also used a variable "section" to help keep track of which chunk of the song is supposed to play. This helped me test the chunks individually, and it insured that when the button was pressed, the song would always start at the beginning. Each section also ends with the line turning the buzzer off in the "else" portion so the last note doesn't keep playing if the button is deactivated.

A tip to my future self would be to take advantage of the fact that this assignment has a lot of repeating code, especially for playing each note. It would be easier to copy and past chunks of the "tone"/"delay" cycle and figure out rhythm afterward than make every note perfect as I go. And speaking of perfection, the song doesn't have to be. The first version of my "introduction" sequence was very cluttered and it sounds a lot better now that I've removed some of the clashing notes.
